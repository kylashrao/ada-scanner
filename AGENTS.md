# Engineering Contract for the US ADA Website Accessibility & Compliance Scanner

These requirements apply to all phases of the web application. They are mandatory.

1. **Stack.** Next.js (App Router, latest stable LTS), TypeScript, Tailwind CSS, static JSON data (zero external paid databases), deployed on Vercel without heavy headless Chromium binaries.
2. **Scanner Architecture & Security.** Build a fast, deterministic server-side HTML/DOM WCAG 2.1 Level A & AA auditor (using lightweight Node HTML parsing, never Puppeteer/Playwright) with strict SSRF protection blocking private IP ranges, localhost, `file://`, and non-HTTP(S) URLs, plus an 8-second fetch timeout and user-agent headers. Also support direct Raw HTML paste scanning. Enforce destination checks at connection time and on every redirect, including for resolved IPv4 and IPv6 addresses. Apply the timeout across redirects and response-body reads. Parse pasted HTML without executing scripts or fetching embedded resources.
3. **Legal & Regulatory Accuracy.** Reference WCAG 2.1 Level AA and US ADA Title II (28 CFR Part 35, including current 2026–2028 DOJ compliance timelines) and Title III public accommodation standards accurately. Explicitly state across the UI and disclaimers that automated scans detect ~30–40% of WCAG issues and do not constitute legal advice or formal legal certification. Present the percentage as an estimate and explain that manual evaluation is needed. Under the DOJ interim final rule effective April 20, 2026, the Title II web and mobile app compliance deadline for state and local governments with populations of 50,000 or more moved from April 24, 2026 to April 26, 2027. For governments with populations under 50,000 and for special district governments, it moved from April 26, 2027 to April 26, 2028. Apply those deadlines only to Title II and describe Title III public accommodations separately. [DOJ Title II compliance guide](https://www.ada.gov/resources/small-entity-compliance-guide/)
4. **AdSense & SEO Compliance.** Every programmatic page must provide substantial unique industry/CMS remediation value (avoid thin content), reserve fixed min-heights on ad containers to prevent Cumulative Layout Shift (CLS), and support `ads.txt` verification.
5. **Quality Gates.** Every phase must pass `npm run typecheck`, unit tests (`node --test`), and `npm run build` with zero errors before advancing.
